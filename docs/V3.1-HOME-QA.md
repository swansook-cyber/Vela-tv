# Vela TV Launcher V3.1 Home setup QA

Target device for final acceptance: TCL Android TV 11,
`TCL-AP-MT9221-01`, firmware `V8-T221T05-LF1V202.000657`.

Vela keeps `MAIN` + `HOME` + `DEFAULT` on its exported `MainActivity` and
`LEANBACK_LAUNCHER` for the TV app list. The Launcher Settings header is the
default Settings pill action. Its two remote-focusable rows request the public
HOME role (Android 10+) or open `Settings.ACTION_HOME_SETTINGS`, and reopen the
system Home settings so the user can switch back. No boot receiver, shell,
root, or stock launcher disabling is involved.

The status is refreshed on return to the app. `PackageManager.resolveActivity`
for `MAIN` + `HOME` decides whether Vela actually receives Home; the HOME role
alone cannot claim success. A canceled request leaves “Not set”. A role grant
that still resolves Home to another launcher reports the system-blocked state.

## Android TV emulator checks

AOSP TV Android 14 (API 34), 1280×720, D-pad and OK key events:
The denial and navigation path is repeatable with
`scripts/test_home_setup_emulator.ps1` on a fresh Android TV emulator.

1. Fresh install: status “Not set as TV home”. D-pad Down from Settings header
   reaches the Vela Home row, and OK opens the Android HOME role dialog.
2. Back cancels the dialog; focus returns to the Vela Home row and status
   remains “Not set as TV home”.
3. D-pad Down focuses “Open system Home settings”; OK opens the system Home
   list. Back returns to Launcher Settings.
4. Selecting Vela and accepting the role makes `dumpsys role` report
   `holders=net.velalab.tvlauncher`. On this AOSP TV image,
   `PackageManager.resolveActivity(MAIN+HOME)` still selects
   `com.google.android.tvlauncher`, and the Home key opens that stock launcher.
   V3.1 correctly reports “TV system does not allow changing Home”.
5. Locally signed V3.1 version code 31000 was installed over the V3 release
   version code 30028 using `adb install -r`. The first install time remained
   unchanged and the existing 7 apps per row and 2 rows below the dock choices
   remained selected. `apksigner` reported the same pinned certificate SHA-256
   as V3.
